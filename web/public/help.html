Personal Brain OS · Field Manual · v3

How to live with it —The Operating Manual

The system's job: you speak, it remembers, it files, it resurfaces. Your job is four habits and two rituals. Sections 01–06 are the daily reality; 07–09 are what each pass added and what is still ahead — so you always know what's next and why.

01 · The Daily Loop

What you do vs. what it does

Teal ticks = your moves. Grey ticks = automatic. Total human time: under 10 minutes a day.

You · all day, anywhere
Capture

Thought arrives → press Action Button → talk → press again. That's the entire habit. Say the tag in the first five words if you know it ("Idea: …", "Todo: …", "Resource: …") and routing costs nothing. Don't organize. Don't type. Don't open Obsidian.

No Action Button? Lock-Screen Voice Memo control, Control Center wave icon, or "Hey Siri, record a voice memo" — all record with the screen locked.

You · 2 taps per memo, batch anytime
Send to Brain

Voice Memos → share → → Brain → optional name, optional tag → "✅ Captured". Recordings are safe in Voice Memos until you do this; batching at lunch or evening is fine. Capture never waits on filing.

Already at the cockpit? The mic button beside the capture box records straight into the pipeline — tap to start, tap to stop, same tag chips. It needs the HTTPS tunnel address (browsers block the mic on a plain http:// one), and it can't record with the screen locked — that's still the Action Button's job.

Plaud: export from the Plaud app and share into CaptureInbox/plaud/ — that works day one. Once you've checked the real path in Plaud Desktop → Preferences, put it in watch_folders and new recordings copy themselves in, originals untouched.

You · any reel, article, or photo, anywhere
Share anything

See a reel, a tutorial, an article — or take a photo of something worth keeping? Share sheet → → Brain Cloud (§08d) → optional quick thought → "✅ Saved to Brain". It lands as a resource note with a description and your thought attached; a photo gets vision-described the same way. Sharing the same link twice merges into one note instead of duplicating it (Pass S3).

System · when you speak Hindi
Hindi → Hinglish

Hindi is transcribed in Devanagari, then rewritten in Roman Hindi. The Hinglish is the note body and the Devanagari original stays in the same note under ## Original (Devanagari) — one note, both halves, nothing lost. Classification and action items read the Hinglish.

No engine configured, or it can't be reached? The note is still written, in Devanagari. A capture is never lost to a formatting step.

System · Mac, every 5 min
Pipeline

Syncthing carries the file over → whisper.cpp transcribes locally → tags route free, untagged goes to Haiku → schema-correct note lands in the right folder → action items appended to today's todos → audio archived, never deleted. Low-confidence guesses park in 00-Inbox instead of being silently misfiled.

You · morning, 2 minutes
Glance + Triage

Open the Cockpit on your home screen (Pass 3 — it shipped; _System/PIPELINE-STATUS.md remains the markdown fallback). The Today screen answers the three questions at a glance: the traffic-light card is calm, teal, or pink; the streak shows yesterday landed. Then the Triage tab — approve or retype, one tap per note.

System · when something breaks
It tells you

Failures go to _failed/ with a plain-English reason and one ntfy push. Silence means healthy. You never re-listen to audio "just to check".

You · Sunday, 15 minutes
Weekly sweep

Inbox to zero · skim capture_log.md · git log the vault · one voice reflection on the week. Done.

02 · The Don'ts

What you never do

Each of these feels productive. Each one is the system eating your life instead of serving it.

  • Don't hand-file or reorganize notes in Obsidian. The pipeline files; you only triage 00-Inbox.
  • Don't edit anything in raw/. Transcripts are immutable sources. Synthesis happens in wiki/, in the weekly compile.
  • Don't invent new folders, types, or tags mid-flow. Vocabulary is locked. Taxonomy itches go to IDEAS-BACKLOG.md.
  • Don't skip a capture because it "isn't important enough." Capture everything; classification is the machine's call.
  • Don't build past the current pass. New feature ideas → DEFERRED.md, one line, keep living.
  • Don't let 00-Inbox pass ~10 items. Past ten, triage becomes a chore; chores die.
  • Don't babysit the pipeline. Fresh heartbeat + quiet ntfy = working. Checking is the old anxiety, not the new system.

Get it live — per tool

One-time, top-to-bottom, one sitting (~90 min). The code is built; this is the wiring.

  • Test on one wav; note binary + model paths
  • brew install ffmpeg if missing
Repo

config.json

  • Copy config.example.json → config.json
  • Fill vault, inbox (Syncthing CaptureInbox), archive, failed paths
  • whisper binary + model paths
  • Random string as api.auth_token; threshold stays 0.7
Shell

API keys

  • export ANTHROPIC_API_KEY=… in ~/.zshrc
  • OPENAI_API_KEY only for the cloud fallback
  • Keys live in env — never in config, never in git
Vault

Git

  • git init the vault if not already
  • One clean commit before the backlog run
  • This is the undo button for every batch and every purge
Phone + Mac

ntfy

  • Install ntfy on iPhone, subscribe to a unique topic
  • Put url + topic in config.json
  • Send a test push; feel the buzz
Sync

Syncthing + Möbius

  • Confirm CaptureInbox syncs phone ↔ Mac
  • Drop a test file on the phone; watch it land on the Mac
  • Möbius folder visible in the Files app
iPhone

Capture triggers

  • Action Button → Voice Memo (records while locked)
  • Build "→ Brain": branch on what came in — audio (unchanged: accept audio → optional name → tag menu → save); URL or text (an Instagram/YouTube share, or any selected text) → optional "Add a thought?" Ask for Input step (your answer is prepended — that becomes the note's clean insight, not glued onto the URL) → tag menu → save as .txt to CaptureInbox; image → "Convert Image to JPEG" action first (this is what makes a HEIC screenshot readable server-side) → optional thought → tag menu → save to CaptureInbox
  • Every branch ends the same way: rename YYYY-MM-DD-HHmm name #tag, save to CaptureInbox, "✅"
  • iOS has no PWA share target (a platform limit, not this app's) — the Shortcut is the whole path for a phone share. On the Mac, the installed cockpit PWA in Chrome DOES appear as a share target — or just paste the link/text straight into Quick Capture
  • Test end-to-end: record/share → file on Mac
Device

Plaud

  • Works day one: export the recording from the Plaud app/Desktop and share it into CaptureInbox/plaud/ — anything in that folder is stamped source: plaud
  • Hands-off: add the folder Plaud Desktop already writes to under watch_folders in config.json ({"path": "…", "source": "plaud"}) — every tick copies new recordings in and never touches your originals. Check the real path in Plaud Desktop → Preferences before you set it
  • Note Pro: sync to the app, point watch_folders at that export folder — same deal
  • A long meeting is transcribed in 10-minute segments and stitched into one note with [hh:mm] markers; it takes a few ticks, and one bad segment never costs the rest
  • The Plaud SDK (pulling straight off the device) is deliberately deferred — see DEFERRED.md
Mic

Record in the cockpit

  • Today screen → the mic button beside the capture box: tap to start, tap to stop
  • Tag chips apply to the recording the same way they apply to typed text
  • Needs the HTTPS (tunnel) address — browsers block the mic on a plain http://192.168… address
  • For capture that survives a locked screen, keep using the Action Button flow
Language

Hindi → Hinglish

  • Hindi speech is transcribed in Devanagari (OpenAI whisper, transcription.language: "hi")
  • It is then rewritten in Roman Hindi, which becomes the note body; the Devanagari original stays in the same note under ## Original (Devanagari)
  • Pick the engine in Settings: Ollama (local, name the model) or OpenRouter (needs OPENROUTER_API_KEY)
  • Engine off or unreachable → the note is still written, in Devanagari. A capture is never lost to a formatting step
Terminal

Run it

  • First: the Backlog Ritual (04)
  • Daily: .venv/bin/python -m pipeline --loop in a tab that stays open
  • Phase 5 makes this permanent on ZimaOS
Browser

Cockpit (Pass 3)

  • cd web && npm ci && npm run build, serve dist/ (or npm run dev)
  • Connect screen: server address + the api.auth_token from config.json
  • Install to home screen (browser menu → Add to Home Screen)
  • Settings (gear, top right): connection, deep links, where every key lives
Mac

API (Pass 2)

  • .venv/bin/uvicorn api.main:app — the server the Cockpit talks to
  • Until it's built, the Cockpit shows its designed "can't reach the server" card — expected, not broken
  • The contract it must implement: web/API-CONTRACT.md
04 · The Backlog Ritual

Your month of audio, finally heard

--backlog
cd brain-cockpit
.venv/bin/python -m pipeline --backlog

Oldest-first, batches of 25. Before each batch it git-commits the vault; after each it prints file → type → destination → confidence and waits. Skim, spot-open two or three notes in Obsidian, press enter. Low-confidence items park in 00-Inbox — triage across the week, not tonight.

Expect 2–4 sittings for a month. Failures land in _failed/ with a reason — retry after fixing, never mid-run.

The day the backlog clears, the 30-day clock starts. Not before.

06 · The Gate

The 30-day test

From the day the backlog clears, live the loop daily. The system passes only if, by day 30, you can name out loud:

3 decisions it improved 3 insights it saved

Fail → kill down to the parts you actually used. Not opened daily by week 3 → same. A tool, not a monument.

07 · The Cockpit

All three passes are live

Same loop, better instrument. None of this changed the habits — it removed friction from them.

Pass 3 · Cockpit UI · shipped
Glance is an app

The morning check is a PWA on your home screen: traffic-light health card (calm / teal "needs your call" / pink "needs a look"), capture streak in big numerals with the 30-day dot row, one resurfaced note with an Open-in-Obsidian link, the triage queue as one-tap cards, quick text capture with the 8 tag chips, and a Settings screen (gear icon) with the connection, deep links, and a map of where every key and path lives. You do: install it to the home screen once; the 2-minute morning ritual now takes 60 seconds. It needs the Pass 2 API running to have data — until then it shows the plain-English "can't reach the server" card.

Pass 4 · Integrations · shipped
One pane of truth

Status cards for every moving part — whisper.cpp, OpenAI fallback toggle, Claude key, ntfy, Syncthing, git, watcher heartbeat — plus deep links out to Obsidian, Dex, Gmail, Calendar, cal.diy, n8n, ZimaOS. You do: nothing daily; visit when something feels off instead of guessing.

Pass 5 · Hardening · shipped
It watches itself

Watchdog pings if the watcher dies, optional 8am digest, auto-retry on transient failures, startup self-check, backup card. You do: trust the silence even more.

08 · Resource OS · Pass 6

Your library, alive

Every tool, book, film, article, recipe, and place you save — as a visual gallery with your one-line insight attached. The pink dot means a resource carries an insight.

You · when you meet a resource
Save it by voice

Action Button → "Resource: the book Alchemy by Rory Sutherland — someone said it's the anti-logic of branding." Done. The pipeline files it as a resource note; the gallery picks it up on next load. Typing a URL into quick capture works too.

You · browsing, deciding, remembering
The gallery

Cover-card grid, filter by category (books / films / tools / recipes / places) and status, search everything. Tap a card → detail drawer: Open source ↗ deep-links out, Open in Obsidian for the raw note, one button advances the status ("Start consuming" → "Mark consumed").

You · the moment you finish something
One takeaway

Marking a resource consumed lands you in a single input: "One takeaway?" Speak-to-type one sentence, save. That sentence is the whole point of the Resource OS — a library of things you consumed with what they changed in you attached. Skippable, never nagging.

System · sample data lifecycle
Seeded → explored → purged

The dashboard launches with ~36 sample resources (sample: true) so you learn it full, not empty. When real resources flow in: the quiet Sample data card at the bottom removes them — scoped to older than 1 day / 1 week / 1 month / all, git-committed before every purge, physically unable to touch a real note. The card disappears when no samples remain.

You · Sunday, folded into the sweep
Shelf check

Filter status = consuming. Anything stalled three weeks? Be honest: archive it or finish it. The library stays alive because it stays honest.

08b · Relationship OS · Pass MW

Nobody good slips away quietly

Every person note in 07-People carries a cadence and a warmth stage. The system watches the clock so you don't have to hold it in your head.

System · 8am, in the digest you already get
The People section

The top three who need you — furthest past their own cadence first, so a 3-day friend a month silent outranks a quarterly contact a fortnight silent. It rides the existing morning push; there is never a second notification.

You · once, before drafting works
Teach it your voice

Settings → My voice: paste 3–5 messages you have actually sent. Until that file exists, drafting refuses — a message that doesn't sound like you is worse than no message.

You · People screen
Draft a message

One tap writes a reconnection message in your voice, referencing the last real thing that happened. If the interaction log is empty it says less rather than inventing a shared history. Edit it in the drawer — it's a draft, not a decree.

You · same drawer
Send it yourself

Copy, or tap the channel button to open WhatsApp / your mail app / LinkedIn with the draft already in it. Nothing is ever sent by the app (§02 — the rule holds here too). You press send, in their app.

You · after you actually reach out
Log contact

Appends a dated line to the interaction log, resets the counter, commits the vault. If the relationship has moved on, it offers the next warmth stage for one tap — offered, never assumed.

System · on request only
Enrich

With a People Data Labs key set, a card can fill in role and company under ## Context, marked origin: ai. Without the key the button says so plainly and everything else keeps working.

You · one tap, from the People screen
+ Target

A name and one channel is enough to start. It writes a proper person note at warmth stage identified — spotted, not yet researched — and commits the vault. Adding someone to the warm-up engine no longer means opening Obsidian; everything else about them can be filled in later, either place.

You · when their profile is stale
Push to Dex · Push to Contacts

Sends a short factual summary of who they are, when you last spoke, what's open, and the next step — out to your own Dex contact and your own Google contact. Updating the Google contact is how it reaches your iPhone, through the Google account you already sync.

The preview is the gate. Tapping the button shows you the exact text first; nothing is written until you press Confirm push. This is not a send — no message goes to the person, ever (§02 holds here too). It updates a contact record, nothing more.

It cannot overwrite your own notes. The app owns only what sits between its <!-- BRAIN-OS --> markers and replaces exactly that. Anything you typed into that Dex description or contact note yourself is left untouched, push after push.

Not set up yet? The buttons become quiet "not configured" pills that say which piece is missing — a Dex key, a dex_id on the note, or one re-consent for Google contacts. Everything else on the card keeps working.

System · in the 8am digest you already get
Ready to push

When people have moved on since their profile last went out, the morning push adds one line naming the count, and the People screen lists them under Ready to push. It stages; it never pushes. Each one still shows you its text and waits for your tap — the constitution's "never bulk-write unreviewed content" applies to what leaves the vault as much as to what enters it.

Empty vault? python scripts/seed_people.py writes six sample people (and --purge removes them) so the screen has something to show before your real ones are in.

08c · MCP · Pass X

Ask Claude Desktop about your own brain

A small server that lets Claude Desktop read the cockpit directly — your status, your people, your todos — and drop a capture in. It holds no data of its own: every answer is a live call to the cockpit you're already running.

Claude Desktop

The config block

Settings → Developer → Edit Config, then restart Claude Desktop:

{
  "mcpServers": {
    "brain-cockpit": {
      "command": "/path/to/brain-cockpit/.venv/bin/python",
      "args": ["/path/to/brain-cockpit/scripts/cockpit_mcp.py"],
      "env": {
        "COCKPIT_URL": "https://your-tunnel-hostname",
        "COCKPIT_TOKEN": "the api.auth_token from config.json"
      }
    }
  }
}

Use the tunnel address if you want it working when the Mac isn't on your LAN; http://127.0.0.1:8000 is fine on the machine itself.

What it can do

Five tools

  • cockpit_status — pipeline health, counts, last run
  • people_list — who's gone quiet, filterable by stage
  • people_draft — a reconnection message in your voice, as text
  • capture_text — drops a thought in the capture inbox
  • todos_today — today's todos from the vault
What it cannot do

The limits are structural

  • It cannot send anything. A draft comes back as text for you to send yourself, exactly like the cockpit's own drawer. There is no tool that contacts anybody, and a test fails the build if one appears
  • It barely writes. capture_text is the only write, and it writes where your own capture box writes
  • It cannot reach your vault except through the cockpit's own routes — no second copy of your notes exists
  • Errors come through in the same plain English the cockpit uses: what happened, likely cause, what to do

The cockpit has to be running for any of this to answer. If Claude says it can't connect, that's the first thing to check — then the URL and token in the config block.

08d · Share anything · Pass S / V2

Save from wherever you actually are

Instagram, YouTube, a web page, or a photo — share it straight from the share sheet, on iPhone or Mac. iOS doesn't let a web app sit in the share sheet, so this is one small Apple Shortcut instead — five minutes, once, and it works everywhere the share icon does.

Build once

The "→ Brain Cloud" Shortcut

  • Shortcuts app → + → name it → Brain Cloud
  • Receive URLs, Text, and Images from the Share Sheet
  • If Shortcut Input is an Image:
    • Resize Image → longest edge 2048px
    • Convert Image → JPEG
  • Ask for Input "Quick thought?" — text, allow empty
  • If input is an Image:
    • Get Contents of URL → POST {cockpit}/api/capture/image?name=Shortcut&insight=[the thought], header Authorization: Bearer <token>, header Content-Type: image/jpeg, Request Body = the resized image
  • Otherwise (a URL or text):
    • Get Contents of URL → POST {cockpit}/api/capture, JSON body {"url": [Shortcut Input], "insight": [the thought]}, same Authorization header
  • Show Notification "✅ Saved to Brain"
Where the pieces come from

Two values, one place

  • {cockpit} — your Railway URL (or tunnel hostname), e.g. https://app-production-xxxx.up.railway.app
  • <token> — api.auth_token from config.json on the server's persisted volume; the same token the cockpit's connect screen uses
  • Both are typed once, into the Shortcut's own actions — nothing lives in a config file on your phone
  • The same Shortcut appears on your Mac automatically (Shortcuts syncs over iCloud) — right-click any file or use the share sheet in Safari
What happens next

Instant save, quiet enrichment

  • The note is written the moment the Shortcut gets 201 back — enrichment (title, cover, transcript) happens after, best-effort, and never blocks or loses the save
  • Your quick thought becomes the note's ## Insight, with the link itself kept out of it (it's already in source_url) — search finds the note by that thought later, not just its title
  • Sharing the same reel or video twice doesn't make two notes — the second thought is added to the first note instead
  • A photo becomes an attachment in the vault plus a one-line AI description of what's in it (and any visible text) — no key set, or the description fails, and the photo is still saved, undescribed, retryable later from the resource's Re-enrich button

Nothing here is a send. The Shortcut talks to your own cockpit and nowhere else — same rule as everything on this page (§02).

08e · Vault sync · Pass H1

One vault, every machine

A cockpit hosted on Railway captures into a vault on a mounted volume — no Obsidian ever opens that folder on its own. This closes the gap: the vault's own git history syncs to a private repo, so the same notes exist on your Mac too.

Set up once

Three steps

  • Create a new private GitHub repo named vault — leave it empty, no README (an empty remote is what the first sync expects)
  • Generate a fine-grained Personal Access Token scoped to only that one repo, with Contents: Read and write
  • On Railway → the app service → Variables, add VAULT_GIT_REMOTE (the repo's HTTPS URL) and VAULT_GIT_TOKEN (the PAT) — no redeploy needed, the watcher and the Sync now button both pick it up on their next run
Then on the Mac

Clone it, point Obsidian at it

  • git clone https://github.com/<you>/vault.git — this is the copy Obsidian opens
  • Open that folder as an Obsidian vault (or point your existing one at it, if the Mac was the vault's original home — see the refusal note below)
  • Either install the Obsidian Git community plugin (auto-pull on a schedule) or make pulling a habit before you check the vault — the cockpit only pushes; nothing pulls into your Mac for you
How it behaves

Safe by construction

  • Every watcher tick (and after each Backlog batch) fetches, rebases the vault's local commits onto the remote, then pushes — never a force-push
  • A real conflict (the same note changed on both sides) aborts the rebase and leaves the vault exactly as it was — Integrations → Vault git-sync names it; resolve by hand (pull normally, fix it in Obsidian or git), then Sync now again
  • Optional on a single-machine setup — Vault git-sync reads "Not configured" and nothing else changes. Set it up the moment a second machine needs the same notes

If the vault already had notes in it BEFORE you created the remote (a Mac-first setup, not Railway-first), the first sync refuses with "unrelated histories" — push that existing vault to the empty remote first, then clone it everywhere else. Don't try to merge two independently-started histories together.
